# Osage — MVP Spec

Terminal SQL IDE in Rust. Data IDE core loop, keyboard-driven, ADBC-native.

## Stack

```toml
[dependencies]
adbc_core = "0.23"
adbc_driver_manager = "0.23"
arrow = "58"
ratatui = "*"          # TUI framework
crossterm = "*"        # terminal backend
tui-textarea = "*"     # editor buffer (cursor/selection/undo)
tree-sitter = "*"
tree-sitter-sequel = "*"  # SQL grammar (verify crate name at build time)
serde = { version = "*", features = ["derive"] }
toml = "*"
keyring = "*"          # OS keychain for secrets
nucleo-matcher = "*"   # fuzzy matching for autocomplete
tokio = { version = "*", features = ["full"] }
color-eyre = "*"
```

Do NOT depend on `databow` — it ships no `[lib]` target. Use `adbc_core` +
`adbc_driver_manager` directly.

## Layout

```
┌──────────────────────────────────────────────────────┐
```

Catalog pane: 30% width, left. Editor: top-right. Results: bottom-right.

## Core types

```rust
struct Profile {
    id: String,              // slug
    name: String,
    driver: String,          // ADBC driver path or name
    uri: String,
    username: Option<String>,
    secret_ref: Option<String>,   // keyring key, never the secret
    options: HashMap<String, String>,
    color: Option<Color>,
}

enum ConnectionState { Disconnected, Connecting, Connected, Errored(String) }

enum NodeKind {
    Catalog,
    Schema,
    Table,
    View,
    Column { data_type: String, nullable: bool },
}

enum LoadState { NotLoaded, Loading, Loaded, Error(String) }

struct CatalogNode {
    kind: NodeKind,
    name: String,
    children: Vec<CatalogNode>,
    load_state: LoadState,
    expanded: bool,
}

struct QueryResult {
    schema: SchemaRef,
    batches: Vec<RecordBatch>,   // MVP: materialize; stream later
    elapsed: Duration,
    row_count: usize,
}

struct QueryError { message: String, span: Option<(usize, usize)> }

struct EditorTab {
    id: usize,
    profile_id: Option<String>,
    textarea: TextArea<'static>,
    result: Option<QueryResult>,
    error: Option<QueryError>,
}

struct App {
    profiles: Vec<Profile>,
    connections: HashMap<String, ConnectionState>,
    catalogs: HashMap<String, CatalogNode>,   // keyed by profile_id
    tabs: Vec<EditorTab>,
    active_tab: usize,
    focus: Pane,                              // Catalog | Editor | Results
    status: String,
}

enum Pane { Catalog, Editor, Results }
```

## Features

### F1 — Connection management
- Profiles read/written at `~/.config/osage/profiles.toml`.
- Secrets stored in OS keychain via `keyring`, referenced by `secret_ref`. Never
  written to TOML.
- Connect/disconnect at runtime without restart.
- Multiple simultaneous connections; each rendered in the connection bar with its
  color tag and state indicator.
- Profile CRUD via a modal form (add/edit/delete).

`profiles.toml` shape:

```toml
[[profile]]
id = "prod-pg"
name = "Production Postgres"
driver = "postgresql"
uri = "postgresql://host:5432/db"
username = "readonly"
secret_ref = "osage/prod-pg"
color = "red"

[profile.options]
adbc.connection.autocommit = "true"
```

### F2 — Catalog browser
- Tree: catalog → schema → table/view → column.
- Lazy load: expanding a node calls ADBC `GetObjects` scoped to that node's depth.
  Never fetch the whole catalog eagerly.
- Cache per `(profile_id, catalog, schema)`. No TTL. Manual refresh only.
- Column nodes render `name  type  [NULL|NOT NULL]`.
- Keybinding inserts fully-qualified `catalog.schema.table` at the editor cursor.

### F3 — Syntax highlighting
- `tree-sitter` SQL grammar, incremental reparse on edit.
- Highlight classes: keyword, string, number, comment, identifier, function, operator.
- Live update on every keystroke, not on run.

### F4 — Autocomplete
- Trigger: on typing after ≥1 char in an identifier position, or explicit key.
- Context detection from tree-sitter parse tree + cursor position:

```rust
enum CompletionContext {
    TableName,
    ColumnName { scoped_tables: Vec<String> },  // tables in FROM/JOIN of current stmt
    Keyword,
    Unknown,   // fall back to blended keyword+table+column list
}
```

- Source: cached `CatalogNode` tree only. No live catalog fetch per keystroke.
- Fuzzy-ranked via `nucleo-matcher`.
- Column suggestions scoped to tables referenced in the current statement, resolving
  aliases (`FROM orders o` → `o.` yields orders' columns).
- Render as a popup below cursor; `Tab`/`Enter` accepts, `Esc` dismisses.

### F5 — Query execution
- Execute the statement under cursor (split on `;`), not the whole buffer.
- Run async; UI stays responsive; show a spinner in the status bar.
- Results → paginated grid. MVP materializes batches; page through in-memory.
- Errors render in the results pane; if the driver supplies a position, highlight the
  span in the editor.

### F6 — Results
- Grid with column headers from the Arrow schema.
- Column widths auto-sized to content, capped; horizontal scroll.
- Page up/down through rows; status bar shows `rows · elapsed · profile`.
- Export current result set: CSV, JSON, Arrow IPC.

## Keybindings

| Key | Action |
|---|---|
| `Ctrl-h` / `Ctrl-l` | cycle pane focus left/right |
| `Ctrl-j` / `Ctrl-k` | cycle pane focus down/up |
| `Enter` / `Space` | expand/collapse catalog node (Catalog focused) |
| `Ctrl-i` | insert qualified table name at editor cursor (Catalog focused) |
| `r` | refresh catalog node under cursor (Catalog focused) |
| `Ctrl-Enter` | run statement under cursor |
| `Ctrl-t` | new editor tab |
| `Ctrl-w` | close tab |
| `Ctrl-e` | export results |
| `Ctrl-Space` | force autocomplete |
| `Tab` / `Enter` | accept completion (popup open) |
| `Esc` | dismiss popup / cancel modal |
| `:` | command palette |
| `Ctrl-q` | quit |

## Build order

1. **M0** — No UI. Binary that connects via `adbc_driver_manager`, runs `GetObjects`,
   prints catalog as JSON. Then runs a query, prints rows. Test against DuckDB and
   Postgres drivers. Exit criteria: ADBC integration trusted.
2. **M1** — ratatui shell, three panes, focus switching, one hardcoded profile.
   Catalog tree renders live. Editor accepts text. `Ctrl-Enter` runs, results dump to
   grid. Ugly is fine. Exit criteria: full loop works end to end.
3. **M2** — F1 connection management (TOML, keyring, modal CRUD, multi-connection).
4. **M3** — F3 syntax highlighting.
5. **M4** — F4 autocomplete.
6. **M5** — F6 results polish: pagination, export, error spans.
7. **M6** — Package: `cargo install osage`, README, demo recording, publish to
   crates.io.

## Constraints

- Arrow is the internal data currency throughout. Don't convert to intermediate
  formats between ADBC and the results pane.
- Catalog introspection is ADBC-generic. No per-database special-casing beyond what
  ADBC itself requires.
- All blocking work (connect, introspect, execute) runs off the render thread.
